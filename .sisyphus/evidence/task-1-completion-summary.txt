TASK OBJECTIVE:
Fix token clobber bug in src/lib/google-auth.ts where the tokens event handler 
destroys refresh_token on disk when Google refreshes the access token.

CHANGES IMPLEMENTED:
- File: src/lib/google-auth.ts
- Lines modified: 237-254 (was 237-248)
- Change type: Bug fix with improved logic

TECHNICAL DETAILS:
The bug was on line 243: `refresh_token: newTokens.refresh_token ?? undefined`

When Google's OAuth2 library refreshes an access token, it emits a 'tokens' 
event with only: { access_token, expiry_date, token_type }

The refresh_token is NOT included in this event (it's only sent during initial 
OAuth consent). The nullish coalescing operator `?? undefined` would resolve 
to undefined, which then overwrote the valid refresh_token in the stored tokens.

SOLUTION:
Build the token update object conditionally:
1. Create tokenUpdate object with all fields EXCEPT refresh_token
2. Only add refresh_token key if newTokens.refresh_token is truthy
3. Pass tokenUpdate to writeAccountTokens

This ensures:
- Token refresh preserves the existing refresh_token
- New refresh_token is saved if Google provides one (during initial auth)
- All other token fields are updated normally
